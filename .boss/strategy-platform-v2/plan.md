# 策略平台 V2 续作实施计划

## 摘要

- 来源为用户指定的架构方案及已有未提交代码，不重复立项。
- 按最新约束只保留主代理与一个实施代理，后端→前端→CI/验证顺序执行。
- 保持数据库事实来源、不可变修订和显式确认发布；旧 API/记录兼容。
- 通过临时 SQLite、真实本机 MariaDB、Flutter widget、浏览器和 Docker 重建证据交付。

## 模块与里程碑

| 模块 | 目标 | 验收 |
| --- | --- | --- |
| M01 权限/状态 | 明确成员授权、owner 转移、草案过期/终态与版本冲突 | 越权拒绝、并发仅一个 owner、单次发布 |
| M02 执行/结果 | cutoff、防未来数据、原生肖算法、一致计分、失败重试 | 固定历史/规则确定性，成功与失败均可追溯 |
| M03 备份/迁移 | 本地包与可选 GitHub、幂等迁移、恢复依赖 | digest 拒绝篡改、导入草稿、断网不影响发布、真实 MariaDB |
| M04 客户端 | 多工作区、分享/撤回、订阅/取消、历史/恢复、AI 确认 | Flutter widget 和真实网页 API 链路 |
| M05 交付 | 非发布 CI、固定兼容工具链、Docker volume | 测试门禁、debug 构建、换容器保留关系 |

阶段风险均用可逆代码与隔离数据验证；未推送代码、未部署生产、未请求或使用真实 GitHub 凭据。详细任务和命令见 tasks.md 与 docs/architecture/strategy-platform-v2-validation.md。
